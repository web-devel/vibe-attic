# Prompts for the kids

These are short examples kids can type themselves. They can use their own words and choose what they want the game to do. Each linked prompt file contains only the message to type. The examples still need M1 rehearsal.

The facilitator prepares the [agent instructions](../AGENTS.md) beforehand. Kids do not need to type technical setup details. See the [rehearsal guide](../docs/m1-rehearsal.md) for setup and checks.

The first request now reuses the [ready game foundation](../foundation/README.md). Later requests generate small edits using the short steps in `AGENTS.md`. The prompt examples below keep the same wording.

## Build, play, change

1. Type [the first game request](01-build-runner.md).
2. Play the game and notice its rules.
3. Follow the facilitator's experiment: predict how a change will affect the jump, change one number, and play again.
4. Choose one new rule and type a request for it.

| Choice | Try it out |
| --- | --- |
| [Double jump](02a-double-jump.md) | Jump again in the air, then try a third jump before landing |
| [Moon mode](02b-moon-mode.md) | Compare a normal jump with a Moon jump |
| [Increasing speed](02c-progressive-speed.md) | Pass five cacti and watch the speed change; then restart |

These choices are alternatives. One new rule is enough for the core workshop.

## If something goes wrong

Use [the repair sentence](repair.md), filling in what you did, what happened, and what you expected. Describe what you actually saw.

Before each change, predict what should happen. Afterward, play to check it. Be ready to show what changed and explain why it works.
